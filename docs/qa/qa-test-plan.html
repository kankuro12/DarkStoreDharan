DarkStore QA Test Plan

Every screen and every button in DarkStore, written as simple checks: what to do, and what you should see. It covers the customer website, the admin panel, the warehouse floor screen, the rider app and the supplier portal, including every sign-up, sign-in, sign-out and password reset. Tick Pass, Fail or Blocked as you go.

Version: main @ 1eb574218 November 2026

Clear every tick and note on this page? This can't be undone.

How to use this page

  • Work through one panel at a time. Use the All panels menu above to show just one.
  • Read Steps, do them, then compare with You should see.
  • Click Pass if it matches. Click Fail if it doesn't and write what happened in the note box. Click Blocked if you couldn't try it, and say why.
  • Your ticks are saved in your own browser. When you finish, press Copy results and paste them into your report.
  • P1 = must work (money, stock, privacy, core flow). P2 = important. P3 = looks and wording.

Before you start

  • Only test on the test site, never the live shop. Orders and payments on the live shop are real.
  • Ask the developer to: load fresh demo data, turn on test SMS (texts are written to a log they can read to you), turn on test signup code (rider and supplier signup code is 123456), and connect eSewa, Khalti and Fonepay sandbox accounts.
  • Keep a phone or a narrow browser window (about 375px wide) ready: the shop and rider app must work on phones.
  • Use two different browsers (or one normal and one private window) when a check needs two people at once.
